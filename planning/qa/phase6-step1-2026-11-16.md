## Helper API for later steps (governments, elections, people)

Read `tools/site/README.md`, the "Tab template" section. In short:

1. Decide the tab keys once, from your data model. Overview is always first and Sources always last; a tab with no content gets no key.
2. Sitemap: `tabs.tab_entries(base, title, description, keys, group=..., crumb=[(label, path), ...])`. Add them from `sitemap.entries()` the way `offices.office_entries` is added.
3. Builder: register every tab path in `PAGES`. Point them all at one function that calls `tabs.build_tabs(site, base, keys, tabs.Head(kind, title, facts), {key: render_fn})` once and caches the result on the site, as `pages/offices.py build_office` does. Citations are shared across the tabs, and footnotes link to the Sources tab.
4. Bodies:
   - `tabs.tab_section(id, title, ...)` for each section;
   - `tabs.status_mark(status, page, note, sources_href)` for status;
   - `tabs.sources_body(page, gaps, notes=[...], title=...)` on the Sources tab.
5. Links in: `offices.office_link(page, oid, tab)` and `offices.href(page, oid, tab)` return None when the page isn't built.
6. Search: give the thing's entries `thing`, so the page pass skips them. Then add tab items with `TAB_KEYWORDS`, as `civic/search.py` does for offices.

## Decisions and why

- **The sitemap gets office tabs from the real model.** `office_tabs` uses `pages/campaigns.cf_all`, cached on the edition. The cost is about 3.5 s per `Site()` in tests, but a tab bar can never link to an unbuilt page, and empty tabs are never generated.
- **Money on office pages is never recomputed.**
  - Local races are `cf_all` races, the same objects the race cards render. The total line uses the card's own format string, and a test asserts that Mayor 2023 is "$610,625.36 spent, $393,342.90 raised" on both pages.
  - News figures are `money_history.reported()` rows. Rounded amounts keep their `as_reported` wording ("nearly $245,000", never ".00"), and each group carries its status mark (SINGLE SOURCE or SECONDARY).
  - State legislators use `legislator_years()`, labelled "A different basis from the local races".
- **The money charts share one scale per office** (`vmax` over every plotted figure) and one label column, so years compare. Primary and general appear as separately labelled groups. Accent and outline only, never party colors (tested).
- **State legislators' charts each keep their own scale.** They count filing years, not cycles, so there is no common cycle axis. They sit two to a row on wide screens.
- **Elections tab:** the newest year's contests are drawn. Each older contest is one summary row (election, winner and share, margin, status) that opens its chart. These folds ship closed even with JS off; the row itself still shows the result. This keeps the Mayor tab at 3.8 screens instead of about 12.
- **Banner rule:** the 2026 UNOFFICIAL banner shows only when the page content (outside the badge legends) has an UNOFFICIAL badge or mark and also names 2026. Why the year check: the 2015 South Bend city election is still labelled unofficial in `results.csv`, and without it, it would trigger the 2026 notice. The wording is unchanged.
- **Header DOM order matches the visual order** (nav, search, chip, Display), so keyboard focus follows the row. The nav, chip and Display are split into two `.head-menu` parts around the search. With JS off, `#primary-nav:target ~ .head-tools` opens both.
- **The Learn dropdown no longer lists the 7 learning paths** (6 links at most). It links to the home page's `#paths` list, which links every path's first stop (tested).
- **Office classes are prefixed `ofh-` (hub) and `ovw-` (overview).** `elections.css` already uses `oh-` and `ov-` bare class names, and check.py forbids duplicates.
- **Offices hub ids:** level ids (`county`, `cities`, `towns`, `townships`, `schools`, `state`) for the Offices dropdown, and `g-<unit_id>` for the breadcrumb's government link. Filters use the existing `table_filter` deep mode. With JS off, it is a plain grouped list of all 127 offices (tested).

## Data problems found (not edited)

1. **`results.csv`, 2015 South Bend city election:** 88 rows (general and primaries) still have status `unofficial` (election-night run of 2015-11-03, stamp not recorded). They show as UNOFFICIAL marks on office Elections tabs. If the certified canvass exists, these rows need it.
2. **`cf_reported.csv`, 2007 general for Mayor of South Bend:** the two candidates' `covers` text differs for the same period ("as of the Oct. 12, 2007 deadline" and "… filing deadline"). Both phrasings print in the chart subtitle.
3. **Name spelling across years:** "Henry Davis Jr" (2023 filings) and "Henry Davis Jr." (2015 news rows) are the same person.
4. **`results.csv` `office_id`:** still blank on all 2,347 rows (existing warning). Office pages use `contests_for_office`, which derives it for 1,132 of 1,243 contests. Contests it cannot map do not appear on any office's Elections tab.
5. **Existing campaign warnings:** Matt Clayton (Clay Township Trustee) and Michelle M Shaw (Clay Township Board) only match filings under another office.
